ANSWER TO YOUR QUESTION: "Which will run? Docker or Compose?"

  EXECUTION ORDER:

  1️⃣  Docker Compose ← YOU RUN THIS FIRST
      $ docker-compose up -d
      └─ Reads configuration from docker-compose.yml

  2️⃣  Docker ← CALLED BY DOCKER COMPOSE
      $ docker build -t hello-world-react .
      └─ Executes Dockerfile (builds image)

  3️⃣  Docker ← CALLED BY DOCKER COMPOSE (again)
      $ docker run -p 80:80 -e NODE_ENV=production ...
      └─ Runs container with settings from compose

  4️⃣  Nginx ← STARTED INSIDE CONTAINER
      CMD ["nginx", "-g", "daemon off;"]
      └─ Serves your React app

  5️⃣  React App ← NOW ACCESSIBLE
      http://localhost
      └─ "Hello World! 🌍"

ANALOGY: Movie Production

  docker-compose = Producer
    ├─ Reads script (docker-compose.yml)
    ├─ Hires crew
    └─ Manages schedule

  docker = Film Crew
    ├─ Builds sets (from blueprints = Dockerfile)
    ├─ Sets up equipment
    └─ Films the movie (creates container)

  Dockerfile = Movie Script/Blueprint
    ├─ Stage 1: Story/Script
    └─ Stage 2: Final Edit

  Container = Movie
    ├─ What people watch
    └─ What users interact with


═══════════════════════════════════════════════════════════════════════

IN PRACTICE:

You type ONE command:
  $ docker-compose up -d

Behind the scenes, THREE things happen:
  1. Docker Compose parses configuration
  2. Docker builds the image (from Dockerfile)
  3. Docker runs the container (with compose settings)

Then you access it:
  http://localhost

═══════════════════════════════════════════════════════════════════════

KEY POINT:

✅ Both Docker and Docker Compose must run
✅ Docker Compose doesn't replace Docker
✅ Docker Compose just automates Docker for you
✅ Docker is like the engine, Compose is like cruise control
